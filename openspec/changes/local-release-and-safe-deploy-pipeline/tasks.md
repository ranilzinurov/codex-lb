# Задачи

## 1. Контракт проверок и выбор CI

- [x] 1.1 Определить области изменений и одну команду `fork-contract`; покрыть
  выбор быстрого/полного уровня модульными тестами.
- [x] 1.2 Применить path filtering к pull request, merge queue и push в `main`,
  сохранив стабильные обязательные контексты через placeholder-шаги.
- [x] 1.3 Добавить явный полный запуск и автоматическое повышение уровня для
  dependency/migration/Docker/runtime/upstream-изменений.
- [x] 1.4 Обновить документацию разработчика о том, когда достаточно
  `fork-contract` и когда требуется полный набор.

## 2. Ограниченный параллелизм frontend-тестов

- [x] 2.1 Зафиксировать исходное время и выявить тесты с общим MSW, timer и
  storage-состоянием.
- [x] 2.2 Изолировать общее состояние либо выделить минимальную именованную
  последовательную группу.
- [x] 2.3 Включить ограниченное число Vitest workers и выполнить несколько
  повторных полных прогонов с сохранением сравнительных замеров.

## 3. Локальная публикация кандидата

- [ ] 3.1 Через тесты определить публичный интерфейс release-команды и
  версионированную JSON-схему манифеста.
- [ ] 3.2 Реализовать проверки опубликованного SHA и чистый detached worktree с
  гарантированной очисткой ресурсов.
- [ ] 3.3 Реализовать buildx `linux/amd64 --push`, временный Docker config и
  повторно используемый кэш без утечки учётных данных.
- [ ] 3.4 Разрешать digest, сверять OCI revision и выполнять один блокирующий
  контроль безопасности опубликованного digest.
- [ ] 3.5 Добавить цель верхнего уровня и руководство локального выпуска.

## 4. Предварительная диагностика и безопасное место на сервере

- [ ] 4.1 Через тесты определить результаты и JSON-схему `deploy doctor`, затем
  реализовать проверки без изменения серверного состояния.
- [ ] 4.2 Реализовать классификацию защищённых и безопасно устаревших образов по
  полным digest/ID.
- [ ] 4.3 Выполнять точечную очистку до итоговой проверки места и завершаться до
  остановки сервиса, если места всё ещё недостаточно.

## 5. Неизменяемое развёртывание и контроль состояния

- [ ] 5.1 Принимать готовый манифест и точный digest, проверять revision и
  отклонять изменяемый тег.
- [ ] 5.2 Через тесты определить версионированный формат отпечатка и правила
  допустимых монотонных изменений.
- [ ] 5.3 Сравнивать отпечатки до и после обновления без вывода секретов и
  инициировать откат при нарушении сохранности.
- [ ] 5.4 Записывать фактически запущенный digest и результат отката в deploy
  state/журнал.

## 6. Сквозная Docker-проверка и эксплуатационная документация

- [ ] 6.1 Создать изолированную Docker-фикстуру первоначального и следующего
  кандидатов с контрольными данными и тестовым секретом.
- [ ] 6.2 Проверить первоначальный запуск, обновление по digest, сохранность,
  неготовый кандидат и откат к фактически предыдущему digest.
- [ ] 6.3 Гарантировать очистку временных контейнеров, сетей, томов, worktree и
  Docker config при успешном и неуспешном исходе.
- [ ] 6.4 Обновить single-host runbook: локальный выпуск, `doctor`, развёртывание,
