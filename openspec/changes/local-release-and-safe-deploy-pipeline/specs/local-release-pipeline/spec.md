# local-release-pipeline Delta

## ADDED Requirements

### Requirement: Кандидат выпуска строится из точного опубликованного коммита

Локальный выпуск SHALL принимать commit SHA, существующий в настроенном
удалённом репозитории форка, и SHALL собирать образ из чистого detached worktree
этого SHA. Неотслеживаемые или незакоммиченные файлы исходной рабочей копии
MUST NOT попадать в контекст сборки. Выпуск MUST завершиться до сборки, если SHA
не опубликован либо невозможно однозначно подтвердить его происхождение.

#### Scenario: грязная исходная рабочая копия не загрязняет выпуск

- **GIVEN** в основной рабочей копии есть незакоммиченный файл
- **AND** выбранный SHA опубликован в репозитории форка
- **WHEN** оператор запускает выпуск выбранного SHA
- **THEN** сборка использует отдельный чистый worktree выбранного SHA
- **AND** незакоммиченный файл отсутствует в контексте сборки

#### Scenario: неопубликованный commit отклоняется

- **GIVEN** локальный commit отсутствует в настроенном удалённом репозитории форка
- **WHEN** оператор пытается выпустить этот SHA
- **THEN** команда завершается до проверки, сборки и публикации образа
- **AND** сообщает, какой Git-инвариант не выполнен

### Requirement: Локальная сборка публикует целевой образ непосредственно в GHCR

Оркестратор SHALL использовать buildx с `--platform linux/amd64` и `--push`,
SHALL публиковать кандидат в настроенный GHCR repository и SHALL использовать
повторно применимый кэш сборки. Учётные данные registry MUST передаваться через
временный Docker config и MUST быть удалены после любого исхода команды.

#### Scenario: выпуск на Mac создаёт совместимый с сервером образ

- **GIVEN** локальная машина имеет архитектуру `arm64`
- **AND** Docker daemon, buildx и учётные данные GHCR доступны
- **WHEN** оператор публикует кандидат
- **THEN** манифест опубликованного образа содержит платформу `linux/amd64`
- **AND** сервер `amd64` может загрузить образ без локальной пересборки

#### Scenario: ошибка публикации очищает временную авторизацию

- **GIVEN** выпуск создал временный Docker config
- **WHEN** buildx завершается с ошибкой
- **THEN** команда возвращает ненулевой статус
- **AND** временный Docker config и временный worktree удалены

### Requirement: Выпуск связывает SHA, revision и неизменяемый digest

После публикации оркестратор SHALL получить registry digest образа и SHALL
проверить, что OCI revision соответствует выбранному полному commit SHA.
Оркестратор SHALL записать версионированный JSON-манифест с repository, SHA,
digest, платформой и результатами обязательных ворот. Готовый к развёртыванию
манифест MUST NOT содержать тег без digest в качестве идентификатора кандидата.

#### Scenario: корректный кандидат получает манифест

- **GIVEN** опубликованный образ имеет ожидаемую платформу и revision
- **WHEN** оркестратор разрешает digest и завершает обязательные ворота
- **THEN** манифест содержит точный `sha256` digest и полный Git SHA
- **AND** манифест помечает кандидат готовым к развёртыванию

#### Scenario: расхождение revision блокирует кандидат

- **GIVEN** revision опубликованного образа не равен выбранному Git SHA
- **WHEN** оркестратор проверяет опубликованный образ
- **THEN** кандидат не получает статус готового к развёртыванию
- **AND** команда не вызывает серверное развёртывание

### Requirement: Опубликованный digest проходит один блокирующий контроль безопасности

Каждый кандидат SHALL пройти один эквивалентный контроль уязвимостей над
опубликованным digest. Контроль SHALL блокировать развёртывание при настроенной
критичности и SHALL сохранять несекретный результат в манифесте. Одинаковый
digest MUST NOT повторно сканироваться до и после публикации в рамках одного
выпуска.

#### Scenario: уязвимость блокирующей критичности останавливает выпуск

- **GIVEN** сканер обнаруживает у опубликованного digest уязвимость
  блокирующей критичности
- **WHEN** выполняется контроль безопасности
- **THEN** манифест отмечает неуспешный контроль
- **AND** серверное развёртывание не начинается

#### Scenario: успешный контроль не дублируется

- **GIVEN** опубликованный digest успешно просканирован
- **WHEN** выпуск переходит к формированию готового манифеста
- **THEN** тот же выпуск не запускает второй эквивалентный скан этого digest
