# single-host-deployment-safety Delta

## ADDED Requirements

### Requirement: Диагностика развёртывания не изменяет сервер

Single-host deploy SHALL предоставлять команду `doctor`, которая проверяет
доступность Docker, конфигурацию, доступ к registry, текущий и предыдущий
digest, свободное место, каталоги данных и возможность создать резервную копию.
Команда SHALL поддерживать человекочитаемый и JSON-вывод. Она MUST NOT
останавливать контейнеры, удалять Docker-объекты, менять state-файл или
записывать в пользовательские данные.

#### Scenario: диагностика обнаруживает недостаток места заранее

- **GIVEN** на сервере недостаточно места для безопасного обновления
- **WHEN** оператор запускает `deploy doctor`
- **THEN** команда возвращает ненулевой статус и объясняет дефицит
- **AND** работающий сервис и deploy state остаются неизменными

#### Scenario: JSON-результат пригоден для оркестратора

- **GIVEN** все предварительные условия выполнены
- **WHEN** `doctor` запускается с JSON-выводом
- **THEN** результат содержит версию схемы и отдельный статус каждой проверки
- **AND** не содержит значения токенов, паролей или API-ключей

### Requirement: Место освобождается только за счёт безопасно устаревших образов

До окончательной проверки места deploy MAY удалить образы прошлых выпусков,
которые не являются активным образом, новым кандидатом или единственным
предыдущим образом отката. Сравнение SHALL использовать полные digest/ID.
Общий Docker prune MUST NOT выполняться. Если безопасной очистки недостаточно,
deploy SHALL завершиться до остановки активного сервиса.

#### Scenario: образ позапрошлого выпуска удаляется до проверки места

- **GIVEN** активный образ и предыдущий образ отката сохранены
- **AND** state содержит ещё более старый неиспользуемый образ
- **WHEN** deploy готовит место для нового кандидата
- **THEN** он может удалить только более старый образ
- **AND** повторяет проверку места до остановки сервиса

#### Scenario: единственный rollback-образ защищён

- **GIVEN** свободного места недостаточно
- **AND** единственный удаляемый крупный образ является предыдущим рабочим
- **WHEN** deploy оценивает безопасную очистку
- **THEN** предыдущий рабочий образ не удаляется
- **AND** развёртывание завершается до остановки сервиса

### Requirement: Развёртывание принимает только проверенный digest кандидата

Deploy SHALL принимать точный digest только из готового манифеста выпуска, SHALL
проверять его revision до переключения и SHALL записывать фактически запущенный
digest в state. Изменяемый тег без digest MUST быть отклонён. Существующие
серверные каталоги данных, файл окружения, токены и API-ключи SHALL повторно
подключаться и MUST NOT пересоздаваться как часть выпуска.

#### Scenario: тег без digest отклоняется

- **GIVEN** оператор передал только изменяемый GHCR-тег
- **WHEN** deploy проверяет кандидат
- **THEN** команда завершается до остановки сервиса
- **AND** сообщает, что требуется неизменяемый digest

#### Scenario: новый контейнер получает прежнее окружение

- **GIVEN** на сервере существуют каталоги данных и файл окружения с ключами
- **WHEN** deploy запускает проверенный новый digest
- **THEN** новый контейнер использует те же внешние каталоги и файл окружения
- **AND** выпуск не записывает новые значения ключей и токенов

### Requirement: Отпечатки подтверждают сохранность состояния и секретов

Deploy SHALL до остановки активного сервиса и после готовности кандидата
формировать версионированные JSON-отпечатки состояния. Отпечатки SHALL
содержать стабильные идентификаторы и необратимые хэши защищённых значений, но
MUST NOT раскрывать сами значения. Потеря записей, смена ожидаемого хранилища
или изменение хэшей защищённых ключей SHALL считать развёртывание неуспешным и
инициировать откат; явно разрешённые монотонные изменения MAY быть приняты.

#### Scenario: ключи и записи сохраняются после обновления

- **GIVEN** исходный отпечаток содержит количество записей и хэши ключей
- **WHEN** кандидат становится готовым
- **THEN** итоговый отпечаток подтверждает отсутствие потери записей
- **AND** хэши защищённых ключей совпадают без вывода исходных значений

#### Scenario: изменение защищённого ключа вызывает откат

- **GIVEN** кандидат готов по healthcheck
- **AND** итоговый отпечаток содержит другой хэш существующего API-ключа
- **WHEN** deploy сравнивает отпечатки
- **THEN** кандидат считается неуспешным
- **AND** deploy возвращает предыдущий digest

### Requirement: Docker-тест проверяет полный жизненный цикл и очищает ресурсы

Репозиторий SHALL иметь автоматический Docker-тест, который во временном
окружении выполняет первоначальный запуск, обновление по другому digest,
проверку сохранности данных и секретов, отказ кандидата и откат к предыдущему
digest. Тест SHALL проверять фактически запущенный digest и SHALL удалять
созданные контейнеры, сети, тома и временные файлы после любого исхода.

#### Scenario: успешное обновление сохраняет состояние

- **GIVEN** временный сервис содержит контрольную запись и тестовый секрет
- **WHEN** тест обновляет сервис с исходного на новый digest
- **THEN** новый digest становится готовым
- **AND** контрольная запись и тестовый секрет сохраняются

#### Scenario: неготовый кандидат откатывается

- **GIVEN** предыдущий digest готов и содержит контрольные данные
- **WHEN** тест развёртывает кандидат, который не проходит readiness
- **THEN** deploy снова запускает предыдущий digest
- **AND** данные сохраняются, а временные Docker-ресурсы удаляются в конце теста
